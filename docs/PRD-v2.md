# AI Research Learning OS — Product Doc v2

---

## 一句话定位

> 为 AI 转型者打造的学习陪伴系统：不是问答工具，而是知道你学到哪了、每天推着你往前走的 AI 导师。

---

## 用户聚焦

### 第一批目标用户：AI 转型者

**画像**

- 有一定技术背景（软件工程、数据分析、产品等）
- 想系统进入 AI/ML 领域
- 不是完全零基础，但没有体系
- 时间碎片化，自律性一般
- 愿意为「真正有效的学习」付钱

**核心痛点（按严重程度排序）**

| 痛点 | 现有解法的缺陷 |
|------|--------------|
| 不知道自己的能力在哪里 | 课程没有诊断，只有进度条 |
| 看完就忘，缺乏强化 | 视频/博客是单向输出 |
| 不知道下一步学什么 | 路线图是静态的，不个性化 |
| 学了没地方用，缺乏反馈 | 没有人知道你学了什么 |
| 缺乏每日驱动力 | 没有仪式感，没有习惯锚点 |

**暂不服务的用户（MVP 阶段排除）**

- 在校研究生（需求是写论文，不是入门）
- 资深算法工程师（需求是 frontier tracking，不是基础体系）
- AI 创业者（需求是速成，容错率高）

---

## MVP 核心假设

> **用户愿意每天打开这个 App**

这是 v1 唯一需要验证的假设。
功能复杂度服从于这一目标，凡是对日活没有直接帮助的功能，全部推迟。

**验证标准（6 周后）**

- D7 留存率 > 40%
- 连续 3 天学习的用户比例 > 30%
- 用户主动完成 Daily Quest 的比例 > 50%

---

## 产品形态

### Mobile-first，习惯优先

对标参考：

- **节奏感**：Duolingo（每日任务 + streak + 成就感）
- **陪伴感**：Character AI（对话有温度，不冷冰冰）
- **深度感**：不像前两者，我们服务的是有一定认知的成人，内容不能幼稚化

不做 Web-first 的原因：学习行为是高频、碎片化的，桌面端不适合习惯养成。

## MVP 功能集（只做这些）

### 1. 入门诊断（Onboarding Assessment）

用户首次进入后，完成 10 分钟的自适应测试：

- 数学基础（线性代数、概率）
- 编程能力（Python、基础 ML 库）
- 已有知识点（自选打标）

输出：**能力快照 + 个性化学习起点**

> 这是差异化的第一步：没有诊断的学习系统是假个性化。

---

### 2. Daily Quest（核心功能）

每天推送，完成时间控制在 15–20 分钟：

```
今日任务
├── 一个概念（精讲 + 类比解释）
├── 一个 Quiz（2–3 题，即时反馈）
└── 一个动手环节（代码片段 / 思维实验）
```

**关键设计原则**

- 内容由系统根据用户当前状态动态生成，不是固定课程
- 错误的 Quiz 会在 3 天后复现（间隔重复）
- Streak 设计：连续打卡有视觉反馈，断了不惩罚，但会温和提醒

---

### 3. Tutor Agent（区别于普通 Chat）

不是通用 AI 助手，而是：

- **知道用户学习状态**的导师
- 能说「你上次做 Attention 机制的 Quiz 错了两题，我们先从这里开始」
- 能主动提问，而不是只被动回答
- 会调整解释深度（根据用户背景和反馈）

技术实现：用户学习记录作为 context，注入每次对话。

---

### 4. Learning Memory（护城河种子）

记录并结构化存储：

```
用户学习状态
├── 掌握的概念（带置信度）
├── 薄弱点（错误率高的知识节点）
├── 学习节奏（什么时间段活跃）
└── 偏好风格（喜欢类比 / 代码 / 公式）
```

这份数据是个性化的基础，也是未来最重要的资产。

---

### 暂不做（推后）

| 功能 | 推后原因 |
|------|---------|
| Paper / arXiv 解析 | 转型者阶段还不到读论文，属于 Phase 2 |
| Research Agent | 需要用户有更高基础，且工程复杂度高 |
| GitHub Repo 分析 | 同上 |
| 社区 / 排行榜 | 冷启动阶段用户量不够，社区做不起来 |
| 课程体系（视频） | 和定位冲突，我们做 AI 导师，不做课程平台 |

## 技术架构（极简 v1）

```
用户
 ↓
Mobile App（Flutter）
 ↓
Tutor Agent
 ├── 用户记忆 Context（Learning Memory）
 ├── RAG（知识库检索）
 └── LLM（claude-sonnet / Qwen3）
 ↓
Daily Quest 生成引擎
```

**知识库构成（人工+半自动）**

- 精选 AI/ML 核心概念（约 200–300 个节点）
- 每个节点：定义 + 类比 + 前置知识 + Quiz 题库
- 初期人工构建，保证质量；后续用 LLM 辅助扩充

> 这个知识库是早期真正的护城河，不是 AI 能力本身。

**技术栈**

- Frontend：Flutter（iOS + Android 同时覆盖）
- Backend：FastAPI + PostgreSQL
- LLM：claude-sonnet-4（主）+ Qwen3（备用/降本）
- Embedding：bge-m3
- 记忆存储：结构化 JSON per user，存 PostgreSQL

## 早期护城河逻辑（重构）

原文档的护城河依赖「大量用户数据积累」，这在早期站不住。

**真正的早期护城河：**

| 护城河 | 说明 |
|--------|------|
| 知识图谱质量 | 人工精选的 AI/ML 概念树，LLM 买不到 |
| 教学设计质量 | Tutor Agent 的提问策略、难度调节逻辑 |
| 用户学习记忆 | 用得越久，系统越懂你，切换成本越高 |
| 习惯绑定 | Streak + 仪式感，迁移摩擦大 |

随规模增长后，用户行为数据和个性化精度才成为真正的壁垒。

## 商业模式（待验证）

**现阶段不锁定模型，先验证留存。**

候选路径：

| 模型 | 优势 | 风险 |
|------|------|------|
| 订阅制（¥39–69/月）| 收入可预期，用户筛选 | 冷启动付费门槛高 |
| Freemium（每日免费 1 次，付费无限）| 低门槛增长 | 免费用户粘性低 |
| 企业/团队版（批量采购）| 客单价高 | 销售周期长 |

**建议节奏：**

1. 前 3 个月：完全免费，验证留存假设
2. 留存验证通过后：引入 Freemium 测试付费意愿
3. 月活 > 5000 后：考虑订阅制

## 三阶段演化路径

```
Phase 1（现在）
AI Tutor + Daily Learning Loop
目标：日活留存验证

Phase 2（留存验证后）
+ Paper 解析 + 知识图谱可视化
+ Research Agent（跟踪前沿）
目标：向算法工程师、研究生延伸

Phase 3（规模化后）
完整 AI Research Learning OS
+ Experiment Agent（实验推荐 + 代码生成）
+ 团队/企业版
目标：从入门到研究员的全链路陪伴
```

## 关键风险

| 风险 | 严重程度 | 应对 |
|------|---------|------|
| Daily Quest 内容质量不稳定 | 高 | 人工审核初期所有生成内容 |
| 用户觉得「又是一个 AI 工具」 | 高 | Onboarding 体验要强调记忆和个性化 |
| LLM 成本超预期 | 中 | 设定每用户每日 token 上限，先测算 |
| 转型者学习需求比预期更多样 | 中 | 内测阶段深度访谈 10 个用户 |
